### 2.4. Mảng 4: Technical SEO / route / slug / schema

**Mục tiêu** (theo spec DVB_FULL_TECHNICAL_SEO_ROUTE_SCHEMA):
- route tiếng Việt không dấu;
- **slug chỉ tạo hoặc đổi khi Admin bấm Generate**;
- URL cũ redirect 308 thẳng tới URL mới;
- canonical, robots, sitemap, OG/Twitter đúng;
- JSON-LD chỉ từ dữ liệu thật;
- không tự bật index.

**Thay đổi người dùng thấy** (khi Owner bật index sau này):
- Mỗi URL cũ của một bài/phòng chuyển hướng vĩnh viễn (308) thẳng sang URL mới.
- URL viết hoa và URL có dấu `/` cuối được đưa về dạng chuẩn.
- Trang `/lien-he` có dữ liệu có cấu trúc ContactPage.
- Trang đặt phòng, tra cứu phòng, cổng đối tác và Admin luôn ở trạng thái noindex.

Hiện tại toàn site vẫn noindex nên Google chưa thấy những thay đổi này.

**Thay đổi Admin thấy:**
- **Ô "Đường dẫn (slug)" mới:**
  - Khi tạo mới, ô hiện **"Chưa tạo"**. Gõ tiêu đề **không** sinh slug.
  - Bấm **Generate** thì server trả đường dẫn. Nếu trùng, hệ thống gợi ý `-2` và Admin phải tự bấm "Dùng …".
  - Sửa tiêu đề, nội dung, SEO hay ảnh rồi lưu thì đường dẫn **giữ nguyên**.
  - **"Generate lại slug"** mở hộp xác nhận "Bạn sắp thay đổi URL công khai… URL cũ / URL mới…".
  - Có bảng **Lịch sử đường dẫn**: URL cũ → 308, ngày đổi, người đổi.
- **Panel "SEO: xem trước và kiểm tra"**, gồm:
  - xem trước kết quả Google;
  - canonical, robots, ảnh OG;
  - cảnh báo: thiếu hoặc quá ngắn/dài/trùng mô tả, thiếu ảnh, chưa Generate, noindex, nội dung mỏng;
  - danh sách schema sẽ phát (✓ hoặc !).
  - Không cho dán JSON-LD tự do.
- **Checklist xuất bản:**
  - bắt buộc đã Generate đường dẫn;
  - combo phải có lịch trình;
  - bài viết phải có tác giả.
- **Công tắc mới** trong Cài đặt → SEO → Dữ liệu có cấu trúc: **"Đã xác minh thông tin doanh nghiệp (TravelAgency)"** (`seo.structuredData.localBusiness`, mặc định tắt).

**Sửa lỗi quan trọng:** trước đây phần frontend coi mô tả thương hiệu dạng rich text là "thiếu", nên **site không bao giờ index được dù Owner đã duyệt**. Lỗi này đã được sửa. Không có giá trị env hay cài đặt index nào bị thay đổi.

**Bước A: Dry-run (chỉ xem, không ghi):**
```bash

```

**Bước B: Tạo các key còn thiếu, không ghi đè:**
```bash
bash scripts/backend.sh seed:public-bootstrap -- --apply --only brand.,site.,home.,about.,seo.pages --actor-email <email Owner>
```
Bước này tạo `about.page`, `home.partner`… và nhập ảnh. **Không** thay key đã có.

**Bước C: Thay các key `DIFFERS` đã được BA duyệt (ví dụ đổi brand trong `brand.identity`, `site.header`, `site.footer`, `home.*`):**
- Với từng key, kiểm xem Owner đã sửa trên production chưa: version > 1, hoặc có audit log khác `public-bootstrap`.

```bash

```
⚠ **`--replace-existing` ghi đè toàn bộ giá trị của key, làm mất mọi chỉnh sửa Admin trên key đó.** Seed có ghi audit log (trước/sau) để có thể khôi phục.
